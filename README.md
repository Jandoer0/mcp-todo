# OmniTask MCP

<p align="center">
  <img src="frontend/public/logo.png" alt="OmniTask" width="140" />
</p>

Веб-приложение для управления задачами со встроенным MCP-сервером для ИИ-агентов.

- **Бэкенд**: FastAPI + SQLAlchemy (SQLite, WAL), JWT-аутентификация — по адресу `/api`
- **Фронтенд**: React + Vite + Tailwind — собирается в `dist/` и отдаётся как статические файлы
- **MCP**: FastMCP через SSE — по адресам `/sse` и `/messages`
- **Изоляция данных**: полная — доски, задачи, теги, списки и палитра привязаны к пользователю; задачи/теги/списки — дополнительно к своей доске

## Возможности

Канбан-доски с задачами, приоритетами, тегами, датами, циклическими задачами (системный список «Регулярные» с жёсткой связью «циклическая ⇔ Регулярные» — список не удаляется, не переименовывается и не меняет свойство; циклические задачи создаются и редактируются только в собственной форме `CyclicTaskForm`, обычная форма задачи циклических полей не содержит; учёт «План vs Факт» — фактические дата и сумма каждой итерации с возможностью корректировки истории задним числом) и мультивалютным бюджетом (валюты на пользователя, курсы к USD, пересчёт в выбранную валюту; базовый слой регулярных платежей отделён от разовых); на карточке задачи с ненулевой суммой показывается сама сумма со знаком и символом валюты задачи (например `+10 000 ₽`), крупные суммы сокращаются (`12,5 млн`, `4,2 тыс.`), полное значение — в подсказке; финансовый график денежного потока по дням (разовые платежи и распределённые потоки, ретроспектива по фактическим платежам + прогноз по плановым, кассовые разрывы, детализация выбранного дня; навигация по дням — стрелки клавиатуры на десктопе и плавающие кнопки на мобильных). Итоги бюджета и график — единая вкладка «Бюджет» с переключателем «Итоги ↔ График» (выбор запоминается) и общим загрузчиком: оба режима считаются в одной валюте расчёта доски. На десктопе списки — горизонтальный ряд колонок (по образцу Planka): перенос карточек drag-and-drop между колонками и внутри колонки с точной позицией вставки (дробный `position` сохраняется на сервере), подсветка приёмника, кнопка «+» в шапке колонки; на мобильных — вертикальная подача со свайп-переносом карточек. Интерфейс адаптивный (мобильные и PWA). Данные каждого пользователя изолированы, а уведомления о событиях задач можно получать во внешних системах через веб-хуки.

## Безопасность

- `SECRET_KEY` — **обязательная** переменная окружения (приложение не стартует без неё): `python3 -c "import secrets; print(secrets.token_urlsafe(48))"`.
- `CORS_ORIGINS` — список разрешённых origin через запятую; по умолчанию CORS отключён (приложение same-origin).
- `ACCESS_TOKEN_EXPIRE_MINUTES` — срок жизни JWT (по умолчанию 480 минут = 8 ч; может переопределяться настройкой `session_expire_minutes` из админки).
- Бутстрап админа: `ADMIN_USERNAME` / `ADMIN_PASSWORD` — при старте аккаунт создаётся/повышается до админа, если админов ещё нет; без пароля генерируется одноразовый (печатается в лог один раз); если env не заданы, админом становится первый зарегистрированный пользователь.
- `MCP_ALLOWED_HOSTS` — защита MCP от DNS-rebinding (список разрешённых Host; пусто = защита выключена). `WEBHOOK_ALLOW_PRIVATE=1` — только для тестов.
- Bulk-операции не раскрывают внутренние ошибки; `user_id`/`id` защищены от подмены через payload; роль из payload регистрации игнорируется.
- Rate-limit и лимиты настраиваются в админке: попытки входа и регистрации (429), максимальный размер тела запроса (413), квота размера БД, лимит досок, минимальная длина пароля.
- Режим обслуживания (`maintenance_mode` в админке): 503 для всех, кроме админов; доступны `/health`, вход и статус регистрации.

## REST API (кратко)

| Домен | Эндпоинты |
|---|---|
| Аутентификация | `GET /api/auth/registration-status`, `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me` |
| Доски | CRUD `/api/boards` (лимит 20 на пользователя; удаление последней доски запрещено) |
| Задачи | CRUD `/api/tasks?board_id=…`, `POST /api/tasks/bulk`, `PATCH /api/tasks/{id}/reorder` (канбан DnD: `{list, position}` — колонка + дробная позиция вставки; инвариант «циклическая ⇔ Регулярные» и запрет done при блокировках проверяются на сервере), `POST /api/tasks/{id}/move` (перенос на свою другую доску), `POST /api/tasks/{id}/cycle/skip`, `POST /api/tasks/{id}/cycle/stop`, `POST /api/tasks/{id}/cycle/complete` (План vs Факт: фактическая дата и сумма в историю итераций), `GET /api/tasks/{id}/cycle/history`, `PATCH /api/tasks/{id}/cycle/history/{log_id}` (корректировка факта задним числом: дата и/или сумма; частичные правки разрешены, только для завершённых итераций), `GET /api/tasks/{id}/changes` (история правок дат/приоритета/описания/суммы/статуса) |
| Списки и теги | CRUD `/api/lists?board_id=…` + `/api/lists/{board_id}/{id}` (системный список «Регулярные» защищён: переименование, смена свойства и удаление запрещены), CRUD `/api/tags?board_id=…` + `/api/tags/{board_id}/{id}` |
| Статистика | `GET /api/summary?board_id=…` |
| Веб-хуки (пользователь) | `GET/PUT/DELETE /api/boards/{board_id}/webhook` (один вебхук на доску), `POST /api/boards/{board_id}/webhook/test` (синхронный тест доставки) |
| Валюты | `GET/POST /api/currencies`, `PUT/DELETE /api/currencies/{id}`, `POST /api/currencies/reorder` (порядок валют: код, название, символ, курс к USD; первая валюта — по умолчанию) |
| Бюджет | `GET /api/boards/{id}/budget` (итоговые суммы и записи в валюте расчёта доски; `regular`/`operational` — базовый слой регулярных платежей vs разовые события; в UI — вкладка «Бюджет» с переключателем «Итоги/График») |
| График | `GET /api/boards/{id}/cashflow` (раскладка сумм по дням: спики/потоки, накопительный баланс, кассовые разрывы; ретроспектива — фактические платежи из истории циклов (`actual: true`), прогноз — плановые суммы) |
| Администрирование | `GET/PUT /api/admin/settings` (все настройки сервера), `PUT /api/admin/settings/allow_registration`, `PUT /api/admin/settings/db_size_limit_mb`, `GET /api/admin/stats`, CRUD `/api/admin/users` (вкл. переключатель webhooks_enabled), `POST/DELETE /api/admin/users/{id}/mcp-token`, `GET /api/admin/users/{id}/boards`, `GET /api/admin/webhooks` (обзор всех вебхуков, только чтение) |
| Диагностика | `GET /api/health` (статус + версия сборки) |

Даты передаются в формате ISO 8601. Все запросы ограничены текущим пользователем (JWT в заголовке `Authorization: Bearer ***`): чужие доски/задачи/теги/списки возвращают 404.

## MCP-инструменты

Все инструменты принимают `auth_token` первым аргументом (MCP-токен генерируется в панели администратора). Инструменты используют тот же сервисный слой, что и REST API, поэтому поведение идентично. Все инструменты работы с задачами требуют `board_id` (получается через `list_boards`):

- `list_boards` — доски текущего пользователя
- `list_tasks(board_id, …)`, `create_task(board_id, …)`, `update_task(board_id, …)`, `delete_task(board_id, …)` — управление задачами (включая циклические поля и сумму `amount`: доход — положительное число, расход — отрицательное; `list_tasks` отдаёт `amount` по каждой задаче); даты (`start_date`/`deadline`) принимаются строками «ГГГГ-ММ-ДД» или ISO 8601
- `get_board_budget(board_id)` — бюджет доски (по свойствам списков): ПЛАН (списки todo/progress), ФАКТ (done), ИТОГО и записи «название [список]: ±сумма», теперь в валюте расчёта
- `search_tasks(board_id, query_str)` — поиск по названию/описанию в рамках доски
- `list_currencies()` — валюты пользователя (код, название, символ, курс)
- `update_currency_rate(code, rate)` — установить курс валюты (стоимость 1 единицы в USD), например 0.011 для RUB: 10 000 RUB ≈ 110 USD
- `manage_cycle(board_id, task_id, action)` — управление циклом: `complete` / `skip` / `stop` / `history`
- `get_project_summary(board_id)` — сводная статистика доски
- `get_my_profile` — ID и роль текущего пользователя
- `list_all_lists(board_id)` — списки указанной доски


## Тесты

```bash
cd backend && SECRET_KEY=dev python3 -m pytest tests/ -q
```

66 тестов: изоляция данных (два пользователя × все роутеры и MCP-инструменты — чужие данные недоступны), безопасность (эскалация привилегий через `role` в регистрации, SSRF-валидация вебхуков, rate-limit, лимиты длины полей и размера тела), веб-хуки (board-scoped API, валидация событий, исключённые события, HMAC-подпись, очистка вебхуков при запрете пользователю, дедупликация уведомлений планировщика), мультивалютность (CRUD валют, изоляция курсов, конвертация бюджета), финансовый график (спики/потоки, накопительный баланс) и реформа циклических задач (системный список «Регулярные», жёсткая связь «циклическая ⇔ Регулярные», учёт «План vs Факт» с корректировкой истории задним числом, базовый слой бюджета, факт-события графика), перенос доски — экспорт/импорт JSON всех задач доски с циклами, блокерами, тегами и историей итераций (с дедупликацией и режимами merge/replace), бэкфилл привязки логов циклов к доске.

## Локальная разработка

```bash
SECRET_KEY=<generated> ./scripts/dev.sh
```

Бэкенд на `:8000`, dev-сервер фронтенда на `:5173` (с прокси к API).

## Деплой

- Образ собирается в `ghcr.io/jandoer0/mcp-todo:latest`.
- Развёртывание: хост `podman-svc`, управление через **Podman Quadlet** (systemd-юнит), прокси — Caddy. В quadlet заданы `DATABASE_URL` и `SECRET_KEY`.
- Обновление: `podman pull` + `systemctl --user restart mcp-todo.service`.
- Фронтенд автоматически перезагружается при изменении версии бэкенда (`BUILD_VERSION`), ручная очистка кэша не требуется.

```bash
# Сборка и публикация образа
echo $(cat /home/agent/.ghcr_token) | podman login ghcr.io -u Jandoer0 --password-stdin
podman build -t ghcr.io/jandoer0/mcp-todo:latest .
podman push ghcr.io/jandoer0/mcp-todo:latest

# Обновление на сервере
ssh podman-svc "podman pull ghcr.io/jandoer0/mcp-todo:latest && systemctl --user restart mcp-todo.service"
```
