# AGENTS.md — OmniTask MCP

Руководство для ИИ-агентов, редактирующих этот проект.

## О проекте
Веб-приложение для управления задачами + MCP-сервер в одном контейнере:
- **Бэкенд**: FastAPI + SQLAlchemy (SQLite, WAL), JWT-аутентификация, доступен по адресу `/api`.
- **Фронтенд**: React + Vite + Tailwind, собирается в `dist/` и отдается как статические файлы.
- **MCP**: FastMCP, работает через SSE по адресам `/sse` и `/messages`.
- **Изоляция**: доски, задачи, теги, списки и палитра цветов строго привязаны к пользователю; задачи/теги/списки — дополнительно к своей доске (`board_id`), кросс-досочное использование запрещено.

## Описание проекта
- Вход на сервер с аутентификацией. Первый зарегистрированный пользователь становится администратором.
- **Изоляция данных (строгая)**: каждый пользователь имеет свои доски (до 20, имя ≤20 симв., описание, цвет из BOARD_PALETTE), а в рамках доски — свои задачи, теги (уникальность имени в рамках доски), списки (в т.ч. копии системных) и палитру цветов. Чужие объекты недоступны (404). Блокирующие задачи могут ссылаться только на задачи той же доски.
- Совместная работа над задачами не предусмотрена.
- MCP-инструменты (все принимают `auth_token` первым аргументом, задачи/списки/статистика требуют `board_id`): `list_boards`, `list_tasks`, `create_task`, `update_task`, `delete_task`, `search_tasks`, `manage_cycle` (complete/skip/stop/history; legacy «done» принимается как «complete»), `get_project_summary`, `get_my_profile`, `list_all_lists` — вызывают тот же `task_service`, что и REST. Даты (`start_date`/`deadline`) принимаются строками «ГГГГ-ММ-ДД» или ISO 8601 и парсятся перед записью в SQLite.
- Bulk-операции: `POST /api/tasks/bulk`; поля `id`/`user_id`/`board_id` игнорируются в payload; ошибки отдаются sanitized.
- Диагностика: `GET /api/health` возвращает статус и версию сборки (`BUILD_VERSION`).
- Общее оформление: тёмно-синий фон (`#35506b`), тёмно-синяя шапка (`#22384d`) с логотипом и названием, белые скруглённые карточки, теги — цветные чипы с белым полужирным текстом. Всегда светлая тема.
- Шапка: логотип и название «OmniTask» слева (скрыты на мобильных), в центре — «барабан» досок — слайд-лента (вся лента досок едет translateX, активная центрируется по замеру offsetLeft; клик по боковой — переключение, по центральной — редактирование; в конце — карточка «+ Создать доску»; количество видимых карточек адаптивно по ширине), справа — иконка пользователя с дропдауном: Профиль / Панель администрирования (только для админа) / Выйти.
- Дашборд:
  - Фильтры задач (на десктопе — в одну строку компактными кнопками; на мобильных — выпадающее меню между кнопками «Списки» и «+ Новая задача»; при открытии меню дашборд накрывается невидимым оверлеем: тап вне меню закрывает его и блокирует доску):
    - Всего задач, К выполнению, В работе, Выполнено, Просрочено, Запланировано — с количеством задач на кнопке. Спящие циклические исключены из первых трёх счётчиков.
  - Облако тегов: цветные чипы; клик фильтрует доску, повторный — снимает фильтр.
  - Кнопка «Списки» — диалог «Управление списками»: пользовательские списки с цветами и порядком; системные «Не начато»/«В работе»/«Готово»/«Архив» нередактируемые (имя/удаление), их цвета недоступны пользовательским спискам; «Не начато» всегда вверху, «Архив» — внизу. Списки у каждого пользователя свои.
  - Кнопка «+ Новая задача» — диалог создания задачи: название, даты начала/окончания, блок «Циклическая задача», приоритет (Низкий/Средний/Высокий, по умолчанию Средний), статус (списки пользователя в их порядке), описание (Markdown), теги (подсказки, 18 пресетов, per-user, сироты удаляются, цвет тега ≠ цветам своих списков), блокирующие задачи, кнопки «Удалить» (красная, слева), «Отмена» и «Сохранить» (справа).
  - Модалки — общий компонент `Modal` (bottom sheet на мобильных, центр на десктопе, скролл дашборда заблокирован).
  - Канбан-доска вертикальная: группы по спискам, сортировка по дате завершения; «Архив» свёрнут по умолчанию.
- Карточка задачи:
  - Свайп (вместо radio-кнопок): **вправо — вперёд по спискам**, влево — назад; на крайних списках «за границу» — удаление. Карточка (белый прямоугольник со скруглениями и тенью) уезжает, обнажая статичную окрашенную подложку на фоне дашборда с надписью целевого списка у внешнего края; после порога (~72px) текст вспыхивает белым. Тап без свайпа открывает редактор.
  - Строки: название (жирное, точка приоритета серая/синяя/красная), описание (одна строка), даты-чипы (слева — начало, справа — завершение; без времени, формат «12 окт.» / «12 окт. 2027» для другого года; серый — день не наступил, оранжевый — сегодня, красный — просрочено), теги (по центру, обрезаются), блокирующие задачи (по центру, обрезаются), для циклических — кнопки «Выполнено» (зелёная), «Пропустить» (синяя), «Остановить» (серая), «История».
  - Карточки в «Готово» и «Архив» — бледные (`opacity-60`), как и спящие циклические.
- Циклические задачи:
  - «Выполнено» → запись в `task_cycle_logs` + автосоздание следующей итерации (дедлайн + интервал × период); выполненная удаляется с доски.
  - «Пропустить» → сдвиг дедлайна без записи в истории. «Остановить» → разрыв цикла, запись в истории. «Удалить» → вся цепочка по `cycle_group_id` (с подтверждением).
  - Умная видимость на бэкенде: скрыта до `дедлайн − reminder_days`; заблокированные видимы всегда; спящие помечены `cycle_dormant`, видны во вкладке «Запланировано» (приглушённые), исключены из счётчиков «Всего задач», «К выполнению», «Просрочено».
- Панель администратора — вкладки:
  - «Пользователи»: CRUD пользователей, роли, переключатель «Разрешить регистрацию», генерация/отзыв MCP-токенов.
  - «Веб-хуки»: CRUD веб-хуков (пользователь, название, URL, секрет HMAC, Telegram chat_id/thread_id, включённые и исключённые события) и кнопка «Тест» — синхронная отправка тестового уведомления с отчётом о доставке.

## Как добавить новую функциональность
- **Бизнес-логика задач**: добавлять в `services/task_service.py`; роутер и MCP-инструмент — тонкие обёртки. Никогда не дублировать логику между `routers/tasks.py` и `routers/mcp.py`.
- **Новый API-эндпоинт**: функция в `routers/*.py` с `@router.get/post/...` + схема в `schemas.py`. Любые запросы фильтровать по `current_user.id` (и по `board_id` — через `get_own_board` из `routers/boards.py`).
- **Новый экран/элемент фронтенда**: компонент в `components/`, данные через хук в `hooks/`, подключение в `App.jsx`, API через `api/client.js`.
- **Новый MCP-инструмент**: `@mcp.tool()` в `routers/mcp.py`, `auth_token` первым аргументом, пользователь через `get_user_from_token`, логика — через `task_service`; даты — через `_parse_dt`.
- **Новая колонка БД**: модель в `models.py` + миграция в `main.py:run_migrations()` (SQLite не добавляет колонки сама; для снятия UNIQUE — пересоздание таблицы, авто-индексы невидимы для inspector).
- **Новое событие веб-хука**: константа в `services/notification_service.py` (EVENTS + _TEXTS) — далее подхватывается админ-формой и валидацией автоматически.

## Соглашения и конвенции
- **Аутентификация**: JWT в заголовке `Authorization: Bearer ***`, axios-интерцептор добавляет автоматически.
- **Область видимости**: все запросы к данным ограничены `current_user.id`; `user_id`/`id` — защищённые поля (игнорируются в payload).
- **Env**: `SECRET_KEY` обязателен (fail-fast), `CORS_ORIGINS` (по умолчанию пусто = CORS выключен), `ACCESS_TOKEN_EXPIRE_MINUTES` (по умолчанию 480), `MCP_ALLOWED_HOSTS`, `DATABASE_URL`, `STATIC_DIR`, `BUILD_VERSION`.
- **Изоляция тегов/списков**: `Tag.user_id`, `TaskList.user_id`, уникальность `(user_id, name)`; палитра тегов проверяется на конфликт только с цветами своих списков.
- **Веб-хуки**: привязаны к пользователю (`Webhook.user_id`) и к доске (`Webhook.board_id`) — получают только события задач своей доски. Тело запроса подписывается HMAC-SHA256 секретом веб-хука, заголовок `X-Hub-Signature-256: sha256=<hex>`; `Authorization` не отправляется. Исключённые события всегда побеждают включённые. Исходящее тело подписывается ровно в том виде, в котором отправляется (`json.dumps(..., ensure_ascii=False)`).
- **Персональные данные в коде**: никакие реальные имена, chat ID, URL и секреты не попадают в placeholder'ы, комментарии, тесты и примеры — только нейтральные шаблоны (`-1001234567890`, `https://example.com/...`).
- **Версионность**: не удалять проверку версии в `useAuth.js`; `ready` в `useAuth` сбрасывается при смене токена (иначе после логина дашборд пуст).
- **Тесты**: `cd backend && SECRET_KEY=dev python3 -m pytest tests/ -q` — запускать после изменений бэкенда.

## Текущее состояние развития
**Выполнено**: discovery MCP (официальный `mcp.sse_app()`), MCP-токены, bulk API, `get_my_profile`, `list_all_lists`, health; полная изоляция данных (теги, списки, палитра); сервисный слой `task_service` (единая логика REST+MCP); pytest-изоляция (17 тестов вместе с веб-хуками); безопасность (fail-fast SECRET_KEY, CORS из env, sanitized ошибки, защищённые поля); производительность (N+1 устранён, WAL, Promise.all на фронте); UX (чипы дат, свайп со статичной подложкой и реверсом, бледные Готово/Архив, оверлей мобильных фильтров).

**Веб-хуки (реализовано)**: модель `Webhook` (user_id, url, secret, chat_id/thread_id, events/excluded_events JSON); сервис `notification_service` (мгновенные события из task_service — REST и MCP; планировщик APScheduler каждые 30 минут проверяет `task_overdue` и `deadline_approaching` с дедупликацией); отправка через `httpx.AsyncClient` без блокировки event loop (`run_coroutine_threadsafe`); HMAC-SHA256 подпись тела в `X-Hub-Signature-256`; admin CRUD `/admin/webhooks` + синхронный тест-эндпоинт `/{id}/test`; вкладка «Веб-хуки» в AdminPanel с кнопкой «Тест»; pytest на CRUD, валидацию, исключения и подпись (всего 17 тестов).

**Планы**: переход на Alembic вместо рукописных миграций в `main.py`.

**Многодосочность (реализовано по новому ТЗ)**: модель `Board` (имя ≤20 симв., описание, цвет из палитры `BOARD_PALETTE` из 20 цветов, лимит 20 досок/пользователь); `board_id` на `Task`/`TaskList`/`Tag`/`Webhook`; полная изоляция досок (теги, списки, задачи, блокеры — только внутри своей доски); миграции с бэкфиллом легаси-данных в доску по умолчанию и перестройкой таблиц tags/task_lists (уникальность имени теперь `(user_id, board_id, name)`); CRUD `/api/boards` (удаление доски каскадно удаляет её данные, последнюю доску удалить нельзя); REST списки/теги/summary принимают `board_id` (пути списков/тегов `/{board_id}/...`); MCP: новый инструмент `list_boards`, `board_id` обязателен во всех инструментах задач; веб-хуки привязаны к доске (`Webhook.board_id`, событие уходит только если доска задачи совпадает, `board_id` в payload); фронтенд: хедер с «барабаном» досок (активная по центру, клик по боковой — переключение, по центральной — редактирование, карточка «+ Создать доску»), иконка пользователя с дропдауном (Профиль / Панель администрирования / Выйти), на мобильных — только иконка и карусель; `BoardForm` (имя до 20 симв., описание, палитра; кнопка «Удалить» — только в режиме редактирования, с подтверждением; после удаления активной доски loadBoards переключает на первую оставшуюся), фон дашборда подкрашивается цветом активной доски; в админ-вебхурах выбор доски пользователя.

**Visual Ergonomics (реализовано)**: сглаживание шрифтов (`antialiased`/`grayscale`, `optimizeLegibility`), базовый `line-height: 1.6`, единый белый текст на карточках досок (читаемость на светлых цветах — мягкая тень), 1px-границы (ring-1/border), GPU-слои (`.gpu-layer`, `will-change-transform`), мягкие оверлеи модалок `bg-slate-900/60`; все анимации отключаются при `prefers-reduced-motion`.

**История изменений задачи (реализовано)**: таблица `task_change_logs`; при каждом update задачи `task_service.log_task_changes` пишет по одной строке на каждое изменённое свойство из `start_date`/`deadline`/`priority`/`description` (было-стало; описание — без текста, в UI общий текст); REST `GET /api/tasks/{id}/changes` (только свои задачи); в диалоге задачи — секция «История изменений» с прокруткой (~6 записей по высоте).

**PWA (реализовано)**: `vite-plugin-pwa` (autoUpdate), precache статики, `navigateFallback` на `index.html` с исключением `/api`, `/sse`, `/messages`; манифест standalone, цвета `#35506b`/`#22384d`, иконки `pwa-192.png`, `pwa-512.png`, `pwa-maskable-512.png`.

## Механика циклических задач (реализована)
Поля модели Task: `is_cyclic`, `cycle_period` (daily/weekly/monthly/yearly), `cycle_interval`, `cycle_group_id`, `reminder_days`; история — `task_cycle_logs`.
- **Выполнено**: запись в историю → новая итерация (дедлайн + интервал × период), выполненная удаляется с доски.
- **Пропустить**: сдвиг дедлайна, без записи в истории. **Остановить**: разрыв цикла, запись «Остановлена». **Удалить**: вся цепочка по `cycle_group_id` с подтверждением.
- Умная видимость считается на бэкенде (`services/task_service.py`); спящие задачи исключены из основных счётчиков и счётчика «Всего задач».
