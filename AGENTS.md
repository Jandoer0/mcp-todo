# AGENTS.md — OmniTask MCP

Руководство для ИИ-агентов, редактирующих этот проект.

## О проекте
Веб-приложение для управления задачами + MCP-сервер в одном контейнере:
- **Бэкенд**: FastAPI + SQLAlchemy (SQLite), JWT-аутентификация, доступен по адресу `/api`.
- **Фронтенд**: React + Vite + Tailwind, собирается в `dist/` и отдается как статические файлы.
- **MCP**: FastMCP, работает через SSE по адресам `/sse` и `/messages`.

## Структура проекта (одна ответственность на файл)
```
backend/
  app/
    main.py            # фабрика приложения: монтирует /api, маршруты MCP, статические файлы
    config.py          # настройки env (SECRET_KEY, DATABASE_URL, BUILD_VERSION)
    db.py              # engine / SessionLocal / зависимость get_db
    models.py          # модели SQLAlchemy (User, Task, TaskList, Tag, TaskCycleLog)
    schemas.py         # модели запросов/ответов Pydantic
    auth.py            # хеширование паролей, JWT, get_current_user / get_current_admin
    routers/
      auth.py          # /auth/register, /auth/login
      tasks.py         # CRUD задач /tasks, циклические задачи (skip/stop/history), умная видимость
      summary.py       # статистика /summary (вкл. счётчик planned)
      admin.py         # управление пользователями /admin/users (только для админа)
      mcp.py           # SSE сервер MCP + инструменты
frontend/
  src/
    api/client.js      # экземпляр axios + функции API по доменам
    hooks/             # useAuth, useTasks (логика состояния и данных)
    components/        # Login, Layout, Dashboard, Board, TaskCard, TaskForm, TagInput, TaskLinkInput, Modal, ListsManager, AdminPanel
    App.jsx            # тонкий корень: связывает хуки + компоненты
```

## Описание проекта
- Вход на сервер с аутентификацией.
- Первый зарегистрированный пользователь автоматически становится администратором сервера.
- Администратору сервера доступна панель администратора.
  Панель администратора включает:
  - Создание и редактирование пользователей.
  - Назначение роли пользователя (администратор/пользователь).
  - Генерацию MCP-токена для ИИ-агента с возможностью отзыва токена.
  - Разрешить/запретить регистрацию новых пользователей.
- Совместная работа над задачами не предусмотрена: каждый пользователь работает со своими задачами.
- Общее оформление: тёмно-синий фон (`#35506b`), тёмно-синяя шапка (`#22384d`) с логотипом и названием, белые скруглённые карточки, теги — цветные чипы с белым полужирным текстом. Режим смены темы удалён, приложение всегда в светлой теме.
- Шапка: логотип и название «OmniTask» слева, кнопки «Панель администратора» и «Выйти» справа.
- Дашборд:
  - Кнопка «Панель администратора» активирует окно панели администратора.
  - Фильтры задач (на десктопе — в одну строку компактными кнопками; на мобильных скрыты и доступны как выпадающее меню между кнопками «Списки» и «+ Новая задача»):
    - Всего задач — все задачи, кроме неактивных (спящих) циклических; кнопка активна по умолчанию; на кнопке указано количество таких задач.
    - К выполнению — список задач, попадающих в список «Не начато»; на кнопке указано количество таких задач.
    - В работе — список задач, не попадающих в списки «Не начато», «Готово», «Архив»; на кнопке указано количество таких задач.
    - Выполнено — список задач, попадающих в список «Готово»; на кнопке указано количество таких задач.
    - Просрочено — список задач, у которых дата завершения просрочена; на кнопке указано количество таких задач.
    - Запланировано — все циклические задачи, включая спящие (у которых не наступило окно видимости); на кнопке указано количество таких задач.
  - Облако тегов: цветные чипы всех тегов; клик фильтрует доску по тегу, повторный клик снимает фильтр. На десктопе — между кнопками «Списки» и «+ Новая задача», на мобильных — отдельным рядом над ними.
  - Кнопка «Списки» активирует диалоговое окно «Управление списками», в котором:
    - Можно создавать пользовательские списки, присваивать им цвета и определять порядок сортировки на дашборде (группами карточек по спискам).
    - Списки «Не начато» (красный цвет), «В работе» (синий цвет), «Готово» (зелёный цвет), «Архив» (серый цвет) являются нередактируемыми.
    - Цвета, присвоенные нередактируемым спискам, недоступны для созданных пользователями списков.
    - Список «Не начато» всегда вверху.
    - Список «Архив» всегда внизу.
  - Кнопка «+ Новая задача» активирует диалоговое окно «Создать задачу», в котором пользователю доступны следующие свойства задачи:
    - Название задачи — поле для ввода однострочного текста.
    - Дата начала — выбор даты и времени.
    - Дата окончания — выбор даты и времени.
    - Блок «Циклическая задача» (расположен между строкой дат и строкой «Приоритет/Статус»): переключатель «Циклическая», выпадающий список «Период» (Ежедневно/Еженедельно/Ежемесячно/Ежегодно), поле «Каждые N периодов» (интервал повторения) и поле «Показывать за (дней)» (окно умной видимости).
    - Приоритет задачи — выпадающий список со стандартными приоритетами (Низкий, Средний, Высокий); по умолчанию активен «Средний».
    Приоритет определяет цветную точку перед названием задачи на дашборде (карточка всегда белая):
      - Низкий — серая точка.
      - Средний — синяя точка.
      - Высокий — красная точка.
    - Статус — выпадающее меню со списками («Не начато», «В работе», «Готово», «Архив» и пользовательские) в том же порядке, в котором их разместил пользователь в диалоговом окне «Управление списками».
    - Описание задачи — поле для ввода многострочного текста с поддержкой форматирования Markdown.
    - Теги — поле ввода названия тега с подсказками подходящих уже созданных тегов в виде списка. Теги имеют уникальный цвет из 18 пресетов. Цвета повторяются, если цвета исчерпаны (то есть тегов больше 18). Теги с одинаковыми именами имеют один цвет. Теги не привязанные ни к одной задаче автоматически удаляются. Цвет тега не совпадает с цветом любого списка.
    - Блокирующие задачи — поле ввода реализовано аналогично тегам, но без цветовой дифференциации (чипы светло-серые). Эти задачи должны быть выполнены до того, как данную задачу можно будет отметить как «Готово».
    - Кнопка «Удалить» красного цвета — в нижнем левом углу диалогового окна.
    - Кнопки «Отмена» (серого цвета) и «Сохранить» (зелёного цвета) — в нижнем правом углу диалогового окна.
  - Все диалоговые окна («Создать/Изменить задачу», «Управление списками», «Панель администратора») используют общий компонент `Modal`: на мобильных — нижний лист (bottom sheet) со внутренним скроллом, на десктопе — центрированное окно; скролл дашборда под окном заблокирован.
  - Блок со списком задач, представляющий собой Канбан-доску, организованную по вертикали, а не по горизонтали.
     - Список карточек задач отсортирован по группам списков и далее по дате завершения задачи в каждой группе.
     - Каждую группу карточек в любом списке можно свернуть кликом по заголовку группы. По умолчанию группа задач «Архив» свёрнута, остальные группы списков развёрнуты.
  Карточка задачи:
    - по горизонтали состоит из трёх сегментов.
    - левый и правый сегменты — Radio Buttons. Левый Radio Button перемещает задачу на список ниже, правый Radio Button — на список выше. При этом правый Radio Button, находящийся в списке «Не начато», — это «Удалить», так как списка выше «Не начато» быть не может. А левый Radio Button, находящийся в списке «Архив», — это также «Удалить», так как списка ниже «Архив» быть не может.
    - центральный сегмент состоит из пяти строк:
      - первая строка — название задачи в одну строку, выделенное жирным шрифтом, перед названием точка приоритета (серая/синяя/красная).
      - вторая строка — описание задачи в одну строку, обычный текст, допускается курсив.
      - третья строка состоит из двух ячеек:
        - первая ячейка — «Дата начала» — выравнивание по левому краю, оформление как у заголовка (высота, жирный цвет);
        - вторая ячейка — «Дата завершения» — выравнивание по правому краю, оформление как у заголовка (высота, жирный цвет); если задача просрочена, дата завершения имеет красный цвет.
      - четвертая строка — «Теги» — выравнивание по центру строки в одну строку (если тегов много, они скрываются за границами строки, видно только те теги, которые входят полностью);
      - пятая строка — «Блокирующие задачи» — выравнивание по центру строки в одну строку (если задач много, они скрываются за границей строки, видно только те задачи, которые входят полностью).
      - для циклических задач дополнительно строка кнопок: «Выполнено» (зелёная), «Пропустить» (синяя), «Остановить» (серая) и «История» (открывает окно истории итераций).
- Циклические задачи:
  - Задача с включенной цикличностью при переводе в «Готово» логируется в историю (`task_cycle_logs`) и автоматически создаётся следующая итерация (тот же заголовок, приоритет, теги, `cycle_group_id`; дедлайн + интервал × период; статус todo); выполненная итерация удаляется с доски.
  - «Пропустить» сдвигает дедлайн на следующий цикл без записи в истории.
  - «Остановить» разрывает цикл (`is_cyclic = False`), фиксирует остановку в истории.
  - «Удалить» циклической задачи удаляет всю цепочку итераций по `cycle_group_id` (с подтверждением).
  - Умная видимость считается на бэкенде: циклическая задача скрыта в основных списках, пока `сейчас < дедлайн − reminder_days`; заблокированные задачи видимы всегда. Спящие задачи помечаются флагом `cycle_dormant` и доступны во вкладке «Запланировано» (приглушённый вид). Спящие задачи исключены из счётчиков «Всего задач», «К выполнению», «Просрочено».

## Как добавить новую функциональность
- **Новый API-эндпоинт**: добавить функцию в соответствующий файл `routers/*.py`, зарегистрировать через `@router.get/post/...`. Обновить или добавить схему в `schemas.py`.
- **Новый экран/элемент фронтенда**: добавить компонент в `components/`, предоставить данные через хук в `hooks/`, подключить в `App.jsx`. Вызывать API через `api/client.js`.
- **Новый MCP-инструмент**: добавить функцию с декоратором `@mcp.tool()` в `routers/mcp.py`. Всегда принимать `auth_token` первым аргументом и определять пользователя через `get_user_from_token`.

## Соглашения и конвенции
- **Аутентификация**: JWT передаётся в заголовке `Authorization: Bearer ***`. Перехватчик axios в `api/client.js` добавляет его автоматически — не устанавливайте его вручную.
- **Область видимости**: Все запросы к задачам ограничены `current_user.id`.
- **Версионность**: Сборка фронтенда включает `BUILD_VERSION` (git SHA) и автоматически перезагружается при изменении версии бэкенда. Не удаляйте проверку версии в `useAuth.js`.

### Порядок действий по завершении задачи (CI/CD)
После внесения изменений в код и их проверки необходимо выполнить следующие шаги для обновления приложения в продакшене:

1. **Пуш кода в репозиторий**:
   ```bash
   git add .
   git commit -m "описание изменений"
   git push origin main
   ```

2. **Сборка и публикация образа в GHCR**:
   ```bash
   # Авторизация (если не выполнена)
   echo $(cat /home/agent/.ghcr_token) | podman login ghcr.io -u Jandoer0 --password-stdin
   
   # Сборка образа
   podman build -t ghcr.io/jandoer0/mcp-todo:latest .
   
   # Пуш образа в реестр
   podman push ghcr.io/jandoer0/mcp-todo:latest
   ```

3. **Обновление сервиса на сервере**:
   ```bash
   ssh podman-svc "podman pull ghcr.io/jandoer0/mcp-todo:latest && systemctl --user restart mcp-todo.service"
   ```
   **Важно**: restart без предварительного `podman pull` перезапускает контейнер из старого образа — новый код не попадёт в продакшен.

4. **Доступ**
   После перезапуска сервер OmniTask доступен для по адресу http://127.0.0.1:8000
   Сервер MCP настроен как omnitask (/home/agent/.pi/agent/mcp-adapter.json)

## Технические требования к развитию MCP (Приоритеты для Lora (Hermes agent))
Для обеспечения полноценного и автономного взаимодействия с ИИ-агентом необходимо реализовать следующее:

1. **Исправление Discovery (обнаружения)**: Обеспечить корректную реализацию протокола MCP, чтобы все инструменты были доступны через `tool_search` без ручного перебора путей.
2. **Оптимизация аутентификации**: 
   - Реализовать механизм долгоживущих API-ключей специально для агентов.
   - Либо добавить инструмент `refresh_token` для самостоятельного обновления сессии агентом.
3. **Расширение функционала API**:
   - **Bulk Operations**: эндпоинты для массового импорта и обновления задач (чтобы избежать сотен мелких запросов).
   - **User Context**: инструмент `get_my_profile` для получения ID и роли текущего пользователя.
   - **Lists Discovery**: инструмент `list_all_lists` для получения списка всех доступных категорий/списков задач.
4. **Улучшение диагностики**: подробные сообщения об ошибках в теле ответа (вместо простых 404/405) и эндпоинт `/health/mcp` для проверки состояния MCP-слоя.
5. **Стандартизация данных**: приведение всех дат к единому стандарту ISO 8601.

## Механика циклических задач (реализована)
Повторяющиеся задачи (например, оплата ЖКХ): поля `is_cyclic`, `cycle_period` (daily/weekly/monthly/yearly), `cycle_interval`, `cycle_group_id`, `reminder_days` у модели Task; история в таблице `task_cycle_logs`.

- **Логика работы**:
  - **Выполнено**: запись о выполнении фиксируется в истории → создается новая копия задачи на следующий цикл (дедлайн + интервал × период), выполненная итерация удаляется с доски.
  - **Пропустить**: дата дедлайна сдвигается на следующий цикл. Запись в истории **не создается** (тихий пропуск).
  - **Остановить**: Цикл разрывается. Задача фиксируется в истории как «Остановлена», новые копии не создаются.
  - **Удалить**: отдельная механика с подтверждением. Полное удаление всей цепочки итераций по `cycle_group_id`.
- **UX/UI**:
  - **Умная видимость** (на бэкенде): задача появляется в активных списках только за `reminder_days` дней до дедлайна; заблокированные задачи видимы всегда.
  - **Отсутствие шума**: в основных списках отображается только текущая активная итерация; спящие задачи доступны во вкладке «Запланировано» и исключены из счётчиков «Всего задач», «К выполнению», «Просрочено».
  - Управление циклом — кнопки «Выполнено / Пропустить / Остановить / История» на карточке циклической задачи.

Отвечай всегда на русском языке.**
